# 基于 FreeRTOS 的设备状态监控与控制系统（Windows 模拟）

这是使用真实 FreeRTOS 内核和 Windows 移植层构建的**模拟设备**，不是 STM32 固件：温度、电压由公式模拟，Windows 本机 TCP 代替物理串口进行默认联调，Windows 的调度无法保证嵌入式实时性。已有独立的 Qt 上位机与它通信。

## 启动

双击总文件夹中的 `启动设备监控系统.cmd`，会打开设备端控制台和 Qt 上位机。上位机选择“FreeRTOS 模拟设备”并点击“连接”。等待运行状态和曲线出现后，可点击“模拟传感器故障”：设备暂停采集约 3 秒，一秒无采样后进入异常状态；采样恢复后经过三个有效采样进入运行状态。也可点击“恢复传感器”提前结束暂停。报警同时受上位机温度阈值影响，设备恢复后温度若仍超阈值，报警会继续显示。关闭两个窗口即可停止系统。

设备端默认只监听 `127.0.0.1:47653`，一次支持一个上位机；端口被占用时启动失败。上位机日志在总文件夹下的 `device_monitor/dist/logs`，设备端事件按 FreeRTOS tick 写入本目录的 `controller.log`；设备端控制台也显示这些事件。

## 结构

- 采集任务周期性生成模拟读数，通过长度为 1 的队列传给控制任务；队列覆盖旧值以保留最新读数。
- 控制任务实现 STARTING、RUNNING、FAULT、RECOVERING 状态机，检测采集超时、处理故障和恢复命令，并将数据和状态放入发送队列。
- 通信任务处理 TCP 或串口字节流及分帧；命令通过队列传递。共享故障设置与日志输出用 FreeRTOS 互斥锁保护。队列满会记录丢帧，不保证可靠投递。
- 上位机通过工作线程接收，显示曲线、设备状态与报警，发送命令，并记录采样和事件。

## 帧协议

ASCII 文本，帧格式为 `$内容*XX\n`，`XX` 是 `$` 与 `*` 之间全部字节的 XOR 校验值的两位十六进制。兼容 CRLF。流式接收支持拆包、多帧和长度限制，错误校验的命令被拒绝。

- 设备发送 `DATA,序号,温度,电压,状态`（状态 0 为运行，1 为非运行）和 `STATE,STARTING|RUNNING|FAULT|RECOVERING`。
- 上位机发送 `CMD,FAULT` 或 `CMD,RESET`，设备接受命令后发送 `ACK,FAULT` 或 `ACK,RESET`。ACK 表示收到命令，状态变化以 `STATE` 为准。协议未提供认证和可靠重传，仅适合本机教学模拟，不能直接作为生产控制协议。

## 串口及真实硬件

设备模拟器也可从命令行执行 `bin\device_controller.exe --com COM3`，使用 Windows COM 口的 115200、8N1、无流控；需自行准备串口线或虚拟串口对，并在上位机选择另一端。该路径与实际 STM32 硬件均未经过实测。真正移植到 STM32 时，需要替换 Windows 移植层、模拟采样和通信驱动，并针对具体开发板实现 UART、中断、时钟及传感器驱动；不能直接烧录此 exe。

## 构建和测试

用 Visual Studio 打开 `controller.vcxproj`，选择 Release / Win32 构建。上位机源码和构建说明位于总文件夹下的 `device_monitor`。运行 `python test_controller.py` 可自动检查校验、拆包、超时、恢复和日志。上位机的 `--controller-test` 用于在设备端已启动时自动检查界面与设备的双向联调。
